# Product Guidelines: Supra L1 SDK

## Prose Style
- **Clarity and Conciseness:** Use clear and direct language. Avoid jargon where possible, or explain it when necessary.
- **Professional Tone:** Maintain a professional and helpful tone.
- **Active Voice:** Prefer the active voice to make instructions more direct and engaging.
- **Consistency:** Use consistent terminology throughout the documentation.

## Branding and Visual Identity
- **Supra Identity:** Align with the official Supra branding guidelines (e.g., logos, colors, typography).
- **Modern and Clean:** The overall aesthetic should be modern, clean, and developer-focused.
- **High-Quality Assets:** Use high-quality icons and diagrams to enhance understanding.

## UX Principles for Developers
- **Intuitive API Design:** Design APIs that are easy to discover and use.
- **Comprehensive Documentation:** Provide detailed documentation, including clear examples and edge-case handling.
- **Helpful Error Messages:** Ensure error messages are informative and provide actionable steps for resolution.
- **Fast Feedback Loops:** Optimize for fast build and test cycles to improve developer experience.
- **Accessibility:** Ensure documentation and examples are accessible to developers with varying levels of experience.

## Code Quality and Documentation
- **TypeScript First:** All examples and snippets should be in TypeScript to reinforce type safety.
- **Up-to-Date Documentation:** Keep documentation in sync with the latest SDK version.
- **Self-Documenting Code:** Write code that is easy to understand, with clear variable and function names.
- **Inline Comments:** Use inline comments sparingly to explain complex logic or important considerations.
